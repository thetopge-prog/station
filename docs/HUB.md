# ستيشن هَب — العمل بلا إنترنت

الشاشات في المطعم لا تتصل بنتفلاي، بل بجهاز صغير داخل المحل («الهَب»). الهَب هو
نفسه هذا التطبيق، يعمل محلياً ومعه قاعدة بيانات صغيرة. عندما ينقطع الإنترنت يبقى
كل شيء يعمل: الكاشير يستلم الطلبات ويطبع، المطبخ يراها، التجهيز يحرّكها، وشاشة
الاستلام تعرضها. وعندما يعود الخط تُرفع كل الطلبات إلى Supabase تلقائياً.

## ما الذي يستمر فعلاً بلا إنترنت

| يعمل | لا يعمل |
|---|---|
| استلام الطلبات وترقيمها وطباعتها | تسجيل دخول موظف جديد لم يدخل من قبل على هذا الجهاز |
| شاشات المطبخ والتجهيز والاستلام | نقاط الولاء والديون (تحتاج قاعدة البيانات) |
| المنيو والصور من آخر نسخة محفوظة | تقارير المدير ونقطة التعادل |
| نقل الطلب: تحت التحضير ← جاهز ← تم التسليم | بوت تلغرام وواتساب |

## التشغيل على جهاز المحل

ضع ملف `.env.local` بنفس متغيّرات Supabase المستعملة في نتفلاي، ثم:

```bash
npm ci && npm run build && npm run hub
```

`npm run hub` يفعل ثلاثة أشياء تُنسى عادةً: ينسخ الملفات الثابتة إلى بناء
`standalone` (وبدونها يفتح المنيو بلا تنسيق ولا صور)، ويستمع على عنوان الشبكة لا
على `localhost` وحده، ويضبط `STATION_HUB=1`.

- `STATION_HUB=1` — هذا وحده ما يحوّل النسخة إلى «هَب». بدونه لا يُفتح أي ملف
  محلي ولا يتغيّر أي سلوك، ولهذا فإن نسخة نتفلاي تبقى كما هي تماماً.
- `STATION_HUB_DB` — مسار ملف قاعدة البيانات (الافتراضي `.hub/station.db`).
  ضعه على قرص الجهاز نفسه، لا على مجلد مزامنة سحابية.
- المنفذ: `npm run hub 3000` أو متغيّر `PORT`.

وجّه الأجهزة اللوحية والشاشات إلى `http://<عنوان-الجهاز>:3000` بدل رابط نتفلاي.
عنوان ثابت للجهاز في إعدادات الراوتر يجنّبك إعادة ضبطها كل مرة.

## كيف يعمل

- **الترقيم**: خط الأرقام مقسوم منذ الترحيل `0025` — المحل يأخذ `1..899`
  وطلبات التوصيل والاستلام من الويب تأخذ `900+`. لذلك لا يمكن أن يتصادم رقم
  أصدره الهَب مع رقم أصدرته السحابة، والرقم المطبوع على الفاتورة هو نفسه الذي
  يصل إلى التقارير لاحقاً.
- **مرة واحدة فقط**: الهَب يولّد `uuid` الطلب محلياً، وهو المفتاح الأساسي في
  السحابة. تكرار الرفع خمسين مرة يسجّل عملية بيع واحدة.
- **الأسعار**: الهَب يطبع الأسماء من نسخته المحفوظة، لكن كل مبلغ يدخل الحسابات
  تعيد `sync_hub_order` حسابه من `menu_items` الحيّة. جهاز بنسخة قديمة لا يستطيع
  تغيير الحسابات.
- **حالة التحضير**: آخر تعديل يفوز (`0025`)، فالطلب الواحد يجهّزه محل واحد في
  لحظة واحدة.
- **الدخول**: الهَب يقبل الجلسة التي شاهد Supabase نفسه يقبلها، ولمدة ١٦ ساعة
  كحدّ أقصى بلا إنترنت. الرمز يُخزَّن مُشفَّراً (SHA-256) فلا يحتفظ الجهاز بأي
  بيانات دخول قابلة للاستعمال. المقابل صريح: جلسة أُلغيت في السحابة تبقى صالحة
  في المحل حتى تنتهي المهلة — وهذا لا مفرّ منه، لأن الإلغاء لا يسافر عبر خط
  مقطوع.

## المؤشّر

يظهر في شريط الموظفين فقط عند الحاجة:

- 🔴 **يعمل بلا إنترنت** — الطلبات تُحفظ محلياً.
- 🟠 **يرفع ٣** — عاد الخط وما زال هناك ٣ عناصر تُرفع.

لا يظهر شيء عندما يكون كل شيء مرفوعاً، ولا يظهر إطلاقاً على نسخة نتفلاي.

## الفحص

```bash
npm test
```

يشمل ٢٥ اختباراً للهَب (الترقيم، رموز الاستلام، التوجيه للمحطات، طابور الرفع).
وللتحقق من الدورة الكاملة مع قاعدة البيانات الحقيقية:

```bash
HUB_LIVE=1 npx vitest run src/lib/hub/live.test.ts
```

يأخذ طلباً والخط مقطوع، يعيد الخط، يرفعه، يتأكد أن الرقم المطبوع لم يتغيّر، ثم
يعيد الرفع مرتين ليثبت أن البيع لم يُسجَّل مرتين، وينظّف كل ما كتبه.
